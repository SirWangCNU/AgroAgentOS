# AI 农场驾驶舱前端重设计计划

## 0. 用户疑问解答

### 这个功能有什么用？

`AI 农场驾驶舱`（`/workspace/farm-agent`）是 AgroAgentOS 的**比赛核心演示页面**，它把一条完整的"感知 → 认知 → 决策 → 执行 → 反馈"农业智能体闭环做成交互式演示：

1. **感知**：选择暴雨、虫害、缺肥、干旱等比赛场景，把传感器、天气、茬口数据注入农场。
2. **认知**：LangGraph Farm Agent 自动选 Skill、做计划、调工具，分析出风险并给出证据。
3. **决策**：AI 生成带证据的行动提案，等待人工批准或拒绝，体现"人在回路"。
4. **执行**：批准后自动生成农事任务，现场人员可开始、提交证据、完成。
5. **反馈**：任务完成后 Agent 复核，事件流记录全过程，形成可追溯的审计链。

对比赛来说，这个页面最能直观回答评委关心的问题："你的智能体到底在干什么？它怎么思考的？人工怎么参与？执行结果怎么验证？"

### 为什么现在感觉设计很乱？

当前页面把所有模块**平铺**在首屏：深绿色 Hero、3 列上排（风险/轨迹/提案）、2 列下排（感知/事件）、任务看板。问题主要有：

- **没有视觉焦点**：视线无处落，不知道先看哪里。
- **Agent 轨迹被挤在中间**：这是最有可解释性价值的部分，却不够突出。
- **比赛操作流程不显著**：场景注入、巡检、审批、执行之间的先后关系没有可视化引导。
- **色彩过多**：深绿 Hero、米色卡片、橄榄绿任务板混在一起，风格不统一。
- **空白状态弱**：未巡检时各模块都显示"暂无"，用户不知道下一步该做什么。

### 更好的方案是什么？

本计划给出的新布局采用 **Z 型视觉动线**，把"智能体是怎么思考的"作为首屏中心：

```
┌─────────────────────────────────────────────────────────────┐
│  步骤引导栏          [农场] [场景] [注入感知] [开始 AI 巡检]   │  ← 控制与流程
├─────────────────────────────────────────────────────────────┤
│                                                             │
│                    Agent 执行轨迹（大屏）                     │  ← 视觉中心
│              Skill → Plan → Tool → Evidence                 │
│                                                             │
├──────────────────────────┬──────────────────────────────────┤
│   当前洞察 / 风险卡片      │   待人工确认的行动提案             │  ← 当前结果
│   （当前 Agent 最关注什么） │   （一键批准 / 拒绝）              │
├──────────────────────────┴──────────────────────────────────┤
│  [展开] 感知读数  |  [展开] 事件流  |  [展开] 任务闭环看板      │  ← 可展开详情
└─────────────────────────────────────────────────────────────┘
```

核心改变：首屏只保留 4 个区域，降低密度；把 Agent 轨迹放大；把感知、事件、任务看板默认折叠。这样既保留所有功能，又让比赛演示更有冲击力。

## 1. Summary

当前 `AI 农场驾驶舱`（`/workspace/farm-agent`）是 AgroAgentOS 的**比赛核心演示页面**，其价值在于展示一条完整的"感知 → 认知 → 决策 → 执行 → 反馈"闭环：

1. **感知**：注入比赛场景（暴雨、虫害、缺肥、干旱）的传感器/天气/茬口数据。
2. **认知**：LangGraph Farm Agent 自动选 Skill、做计划、调工具、生成风险证据。
3. **决策**：AI 提出带证据的行动提案，等待人工批准或拒绝。
4. **执行**：批准后生成农事任务，现场人员可开始、提交证据、完成。
5. **反馈**：任务完成后 Agent 复核，事件流记录全过程。

用户反馈当前页面"信息太密集"，且希望比赛演示突出 **Agent 可解释性**。本计划对 `FarmAgent.tsx` 及相关组件进行信息架构重组，降低首屏密度，把"智能体是怎么思考的"作为视觉中心，同时保留完整闭环能力。

## 2. Current State Analysis

### 2.1 已读关键文件

- `frontend-react/src/pages/FarmAgent.tsx`：页面主文件，当前把所有模块平铺展示。
- `frontend-react/src/components/farm-agent/AgentRunTimeline.tsx`：Agent 执行时间线。
- `frontend-react/src/components/farm-agent/FarmRiskCard.tsx`：风险卡片。
- `frontend-react/src/components/farm-agent/ActionProposalCard.tsx`：行动提案卡片。
- `frontend-react/src/components/farm-agent/FarmTaskBoard.tsx`：农事任务看板。
- `frontend-react/src/components/farm-agent/SensorPanel.tsx`：近 N 天感知读数。
- `frontend-react/src/components/farm-agent/FarmEventTimeline.tsx`：近 N 天事件流。
- `frontend-react/src/types/farmAgent.ts`：类型契约。
- `app/api/v1/farm_agent.py` 与 `app/services/farm_agent_service.py`：后端 SSE 巡检、提案、任务接口。

### 2.2 当前问题

1. **信息平铺，没有焦点**：首屏同时出现 Hero、3 列上排（风险/轨迹/提案）、2 列下排（感知/事件）、任务看板，视线无处落。
2. **Agent 轨迹被挤在中间**：作为最有"可解释性"价值的组件，尺寸和位置都不够突出。
3. **比赛操作流程不显著**：场景选择、注入、巡检、审批、执行之间的先后关系没有可视化引导。
4. **风格不统一**：深绿色 Hero、米色风险卡片、深绿色时间线、米色事件卡片、橄榄绿任务板，色彩过多。
5. **空白状态提示弱**：未巡检时各模块都显示"暂无"，用户不知道下一步该做什么。

## 3. Proposed Changes

### 3.1 总体布局：从平铺到"以 Agent 轨迹为中心"

新布局采用 **Z 型视觉动线**，首屏只保留 4 个核心区域：

```
┌─────────────────────────────────────────────────────────────┐
│  步骤引导栏          [农场] [场景] [注入感知] [开始 AI 巡检]   │  ← 控制与流程
├─────────────────────────────────────────────────────────────┤
│                                                             │
│                    Agent 执行轨迹（大屏）                     │  ← 视觉中心
│              Skill → Plan → Tool → Evidence                 │
│                                                             │
├──────────────────────────┬──────────────────────────────────┤
│   当前洞察 / 风险卡片      │   待人工确认的行动提案             │  ← 当前结果
│   （当前 Agent 最关注什么） │   （一键批准 / 拒绝）              │
├──────────────────────────┴──────────────────────────────────┤
│  [展开] 感知读数  |  [展开] 事件流  |  [展开] 任务闭环看板      │  ← 可展开详情
└─────────────────────────────────────────────────────────────┘
```

### 3.2 具体改动

#### A. `frontend-react/src/pages/FarmAgent.tsx`

**改动点：**

1. **替换 Hero 为步骤引导栏（Stepper）**
   - 用 5 步轻量步骤条替代大 Hero：准备场景 → 运行巡检 → 查看证据 → 批准行动 → 执行任务。
   - 当前步骤高亮，已完成步骤显示对勾，未完成步骤置灰。
   - 控制按钮（农场选择、场景选择、注入感知、开始巡检）放在步骤条右侧，形成"流程 + 控制"一体化头部。

2. **Agent 执行轨迹放大为左侧/中央主面板**
   - 占首屏 60% 宽度，高度固定（如 `h-[28rem]`），独立滚动。
   - 保留深色主题，但统一圆角、字体、间距。
   - 当前运行步骤高亮，已完成步骤折叠为单行，可点击展开详情。

3. **右侧"当前洞察"面板**
   - 合并原"风险态势"和"待确认提案"，只展示**当前 Agent 刚生成的、最需要关注**的 1-2 张卡片。
   - 每张卡片包含：风险标题、置信度、关键证据 1 条、建议行动 1 条、批准/拒绝按钮。
   - 更多历史风险/提案通过"查看全部"弹窗或下拉面板的第二页展示。

4. **可折叠的详情区**
   - 感知读数、事件流、任务看板默认折叠为 3 个横向折叠面板（Accordion）。
   - 点击后展开，避免首屏信息过载。
   - 任务看板在存在"待执行"任务时自动展开并显示小红点。

5. **统一视觉风格**
   - 主色调沿用品牌绿 `#1f6a4b`，背景使用柔和的 `#f8faf8` / `#ffffff`。
   - 所有卡片统一为白底、细边框、小圆角（`rounded-2xl`）、柔和阴影。
   - 删除深绿色 Hero 和多种米色背景，仅用 1-2 种强调色区分状态（风险等级、任务状态）。

#### B. `frontend-react/src/components/farm-agent/AgentRunTimeline.tsx`

**改动点：**

1. 支持**当前步骤高亮**与**已完成步骤折叠**。
2. 为 `tool_call` 事件增加可展开的工具参数与返回摘要。
3. 为 `plan` / `replan` 事件显示计划步骤列表（带序号）。
4. 为 `skill_selected` 事件显示 Skill 名称和选择理由（如果后端有返回）。
5. 运行完成时顶部显示"巡检完成，生成 X 条风险、Y 项提案"的总结条。

#### C. 新增 `frontend-react/src/components/farm-agent/InspectionStepper.tsx`

**职责：**
- 纯展示组件，接收当前步骤索引。
- 步骤：准备场景 → 运行巡检 → 查看证据 → 批准行动 → 执行任务。
- 与页面控制按钮状态联动（例如：未选场景时"运行巡检"不可用）。

#### D. 新增 `frontend-react/src/components/farm-agent/CurrentInsightCard.tsx`

**职责：**
- 展示当前最重要的 1 条风险或 1 个待确认提案。
- 包含：标题、严重等级 badge、置信度、1-2 条证据摘要、行动按钮。
- 如果无当前洞察，显示引导文案"启动巡检后，AI 发现的最高优先级风险会出现在这里"。

#### E. 调整 `frontend-react/src/components/farm-agent/FarmTaskBoard.tsx`

**改动点：**

1. 作为可折叠面板内部内容，减少上下外边距。
2. 任务列保持 4 列，但使用更紧凑的卡片。
3. 存在进行中的任务时，面板标题显示脉冲圆点提示。

#### F. 调整 `frontend-react/src/components/farm-agent/SensorPanel.tsx` 与 `FarmEventTimeline.tsx`

**改动点：**

1. 作为可折叠面板内部内容，默认隐藏。
2. 移除独立卡片标题中的大图标，改为更轻量的列表形式。
3. 空状态文案优化为"暂无数据"并提示如何注入场景。

## 4. Assumptions & Decisions

1. **不改后端 API**：本次只改前端展示，依赖现有 SSE `/farm-agent/inspections/stream`、提案、任务接口。
2. **保留所有现有功能**：场景注入、风险展示、提案审批、任务闭环看板均保留，只是默认折叠或聚合展示。
3. **Agent 可解释性优先**：把执行轨迹作为首屏核心，是因为用户明确选择此方向，也符合比赛评委"AI 怎么思考的"关注点。
4. **移动适配保持现状**：本次重点优化桌面端比赛演示体验，移动端保持可用即可。
5. **颜色体系沿用现有 token**：不引入新 Tailwind 自定义颜色，使用现有 `emerald`、`slate`、`amber`、`rose` 等语义化色板。

## 5. Verification Steps

1. `npm run build` 通过，无 TypeScript 错误。
2. `npm run dev` 启动后，`/workspace/farm-agent` 页面正常渲染。
3. 未巡检时：首屏只显示步骤引导栏 + Agent 轨迹空状态 + 当前洞察空状态 + 三个折叠面板。
4. 选择场景并注入后：步骤条"准备场景"变为完成，感知面板可展开查看注入数据。
5. 开始巡检后：Agent 轨迹实时滚动，当前步骤高亮，右侧当前洞察卡片随新风险/提案动态更新。
6. 生成提案后："待确认行动提案"面板出现可批准/拒绝的卡片，步骤条"查看证据"完成。
7. 批准提案后：任务看板自动展开并显示新生成的待执行任务。
8. 完成一个任务闭环：任务状态变更正确，事件流中新增记录。

5. 调整 `FarmTaskBoard.tsx`、`SensorPanel.tsx`、`FarmEventTimeline.tsx` 为可折叠面板内容。
6. 运行构建和手动验证。
