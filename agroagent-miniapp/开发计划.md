# AgroAgentOS 智农助手 - 微信小程序开发计划

> 基于 `agroagent-miniapp/index.html` 设计稿，复用现有 FastAPI + LangGraph 后端，快速落地一款微信小程序。

---

## 一、设计稿分析

设计稿包含 4 个核心页面，采用「仿豆包」设计理念，主品牌色 `#16a34a`（绿色）：

| 页面 | 路径建议 | 核心功能 |
|------|----------|----------|
| 对话首页 | `pages/chat/home` | AI 头像 + 4 个快捷入口（拍照识别病虫害 / 种植咨询 / 天气农事 / 农场看板）+ 猜你想问 |
| 对话页 | `pages/chat/conversation` | 流式 SSE 对话、思考中动画、Markdown 渲染、引用来源、联网搜索/知识库标签 |
| 工作台 | `pages/workspace/index` | 搜索栏 + 数据统计 + 常用工具卡片 + 更多功能列表 + 最近使用横滑卡 |
| 我的 | `pages/profile/index` | 用户头像/姓名/角色 + 个人信息/我的农场/通知设置 + FAQ/反馈/关于 |

底部 TabBar：对话、发现、工作台、我的（设计稿中「发现」页未展开，需补充）。

## 二、技术选型

| 维度 | 选型 | 理由 |
|------|------|------|
| 框架 | **微信原生小程序** | 设计稿页面少、交互以列表+对话为主，原生开发最轻量、SSE 兼容性最好 |
| UI 组件 | 自绘 + `Vant Weapp`（可选） | 设计稿样式高度定制，自绘 W/WXSS 还原度最高；复杂表单可引 Vant |
| 状态管理 | 原生 `globalData` + `Behavior` | 4 个页面无需引入 MobX/Redux |
| 网络请求 | 封装 `wx.request` + **SSE 插件** | 小程序原生不支持 EventSource，需用 `wx.request` 的 `enableChunked` 或 `wx.connectSocket` 转 SSE |
| Markdown 渲染 | `towxml` 或 `wxParse` | 对话页 AI 回复含 Markdown（标题、列表、加粗） |
| 图表 | `ec-canvas`（ECharts 小程序版） | 农场看板需要折线/柱状图 |

> **不选 uni-app/Taro 的原因**：后端已有 React Web 端，小程序仅作移动端补充；原生开发体积最小、SSE 流式处理最可控，且无需额外编译链路。

## 三、后端 API 映射（复用现有接口）

后端已实现 16 个路由，几乎可 1:1 对接设计稿功能：

| 设计稿功能 | 后端接口 | 说明 |
|-----------|---------|------|
| AI 对话（流式） | `POST /api/v1/chat/stream` | SSE，需处理 chunked |
| 拍照识别病虫害 | `POST /api/v1/image/*` | 上传图片 → 分析 → 展示防治建议 |
| 天气与农事建议 | `GET /api/v1/weather?location=` | 已有城市/经纬度两种入参 |
| 农场数据看板 | `GET /api/v1/farms/*` | 农场管理 + 统计 |
| 市场行情 | `GET /api/v1/market/overview?crop=&location=` | 价格/供需/政策聚合 |
| 营销文案 / AI 视频 | `POST /api/v1/video/*` | 已有生成类接口 |
| 知识库 | `GET /api/v1/documents/*` | 文档检索 |
| 登录注册 | `POST /api/v1/auth/login`、`/register` | JWT，小程序可对接 `wx.login` 换 token |
| 会话历史 | `GET /api/v1/sessions/*` | 对话列表 |

**后端需补充的接口**（小程序特有）：
1. `POST /api/v1/auth/wx-login` — 接收 `code`，调用微信 `code2Session` 换 openid，签发 JWT。
2. 农场看板聚合统计接口 `GET /api/v1/farms/dashboard`（如后端无）。

## 六、关键技术难点与对策

### 1. SSE 流式对话（最大难点）
小程序**不支持** `EventSource`。两种方案：

**方案 A（推荐）：`wx.request` 分块接收**
```js
const task = wx.request({
  url: `${BASE_URL}/api/v1/chat/stream`,
  method: 'POST',
  enableChunked: true,
  header: { 'Authorization': `Bearer ${token}`, 'Content-Type': 'application/json' },
  data: { session_id, question },
  responseType: 'text',
  success() { /* 流结束 */ }
})
task.onChunkReceived(res => {
  // res.data 是 ArrayBuffer，需逐行解析 "data: {...}\n\n"
  const text = decodeChunk(res.data)
  parseSSELines(text).forEach(evt => updateMessage(evt.content))
})
```
注意：`onChunkReceived` 的数据是 `ArrayBuffer`，需手动 UTF-8 解码 + 按 `\n\n` 切分 SSE 事件。

**方案 B**：后端加 WebSocket 端点（`/ws/chat`），小程序用 `wx.connectSocket`，对齐性更好但需后端改造。

### 2. JWT 登录态
- 小程序无 Cookie，token 存 `wx.setStorageSync`
- 每次请求在 header 注入 `Authorization: Bearer xxx`
- 401 时静默调 `wx.login` 刷新 token，失败再跳登录页

### 3. 图片上传识别
- `wx.chooseMedia` 选图 → `wx.uploadFile` 上传到 `/api/v1/image/...`
- 注意小程序上传单次限 10MB，需 `wx.compressImage` 压缩

### 4. Markdown 渲染
- AI 回复含 `**加粗**`、`- 列表`、标题，需用 `towxml` 转 WXML 节点
- 流式场景下需增量渲染（每次 token 到达追加并重新 parse 末段）

### 5. 设计稿还原
- 设计稿用 `375×812`（iPhone X），小程序用 `rpx`（750 设计稿基准），需 `×2` 换算
- CSS 变量在小程序中需用 `page { --brand: #16a34a; }` 定义

## 七、风险与注意事项

| 风险 | 对策 |
|------|------|
| `request` 合法域名必须 HTTPS 且备案 | 开发期在开发者工具勾选「不校验域名」；上线前配好域名 |
| 小程序包体限制 2MB（主包） | 把诊断/天气/市场等子页面放分包 |
| SSE 在弱网下可能断流 | 加心跳 + 自动重连 + 已接收内容续传 |
| AI 回复含敏感词被审核拦截 | 后端已有内容过滤；小程序侧加关键词兜底 |
| 微信登录需后端 `code2Session` | 后端 `auth/wx-login` 需配置 `WX_APPID`/`WX_SECRET` |
