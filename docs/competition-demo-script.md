# 比赛演示剧本 — AgroAgentOS 农场管理 × AI 驾驶舱联动

> 目标时长：14 分钟（可压缩到 10 分钟或扩展到 20 分钟）
> 演示前提：后端 `uvicorn app.main:app --port 9800` + 前端 `cd frontend-react && npm run dev` 均已启动
> 数据准备：已创建农场"南京试验农场" + 3 个地块（A1 水稻 / A2 玉米 / A3 大豆），与 fixture 字段名一致

---

## 二、10 步演示剧本

### 步骤 1 — 自我介绍 + 项目背景（1 min）

**操作**：投影封面页

**讲解要点**：
> "AgroAgentOS 是 FastAPI + LangGraph 多 agent 农业平台。今天演示的核心是农场管理与 AI 驾驶舱的联动——在没有真实硬件的情况下，通过场景化感知数据注入，完整呈现感知-认知-决策-执行-反馈闭环。"

---

### 步骤 2 — 展示 Farms 页面（1 min）

**操作**：进入 `/workspace/farms`，点击 A1 地块

**预期效果**：
- 左侧地块列表高亮 A1
- 地块列表下方出现"当前茬次"卡片：水稻 · 分蘖期 · 生育期进度条
- 茬次卡片下方出现"近 30 天事件流"时间线（此时可能为空，属正常）

**讲解要点**：
> "农场管理是事实底座。茬次表（CropSeason）把作物的生命周期结构化——从播种到收获的每个阶段都有记录。下方的农场事件时间线是不可变记忆，所有作业都会留痕。"

---

### 步骤 3 — 切到 Dashboard（1 min）

**操作**：进入 `/workspace/dashboard`

**预期效果**：
- Hero 区显示"今日农场智能决策台" + 4 个概览卡片
- 下方"农场健康分"卡片：圆形进度条显示 100 分（绿色），子指标全为 0
- 再下方是系统运行状态 + 功能模块

**讲解要点**：
> "Dashboard 是经营视图。健康分 100 分意味着当前无风险积压。这个分数不是拍脑袋，而是基于待确认提案的风险等级和逾期任务数算出来的——所有指标都来自下面的真实数据。"

**健康分公式**：`100 - 高风险×20 - 中风险×10 - 逾期任务×5`

---

### 步骤 4 — 切到 FarmAgent 页面（1 min）

**操作**：进入 `/workspace/farm-agent`，选择"南京试验农场"

**预期效果**：
- 三栏布局：左侧风险态势 / 中间 Agent 时间线 / 右侧提案列表
- 顶部出现"比赛场景"选择器 + "注入感知数据"按钮
- 下方出现"近 7 天感知读数"面板（空）和"近 14 天事件流"时间线（空）

**讲解要点**：
> "AI 驾驶舱是闭环核心。这里把感知、认知、决策放到一个界面。上方的场景选择器是比赛演示的关键——没有硬件，我们用 fixture 文件模拟田间传感器读数。"

---

### 步骤 5 — 注入 rainstorm 场景（1.5 min）

**操作**：
1. 在场景选择器中选择"暴雨内涝"
2. 点击"注入感知数据"按钮

**预期效果**：
- Toast 提示"场景 rainstorm 注入完成：新增 6 条感知、1 个茬次，覆盖地块 A1"
- "近 7 天感知读数"面板出现 A1 地块的读数：
  - 土壤含水量 95%
  - 降雨量 158mm
  - 等
- "近 14 天事件流"可能出现茬次创建事件

**讲解要点**：
> "点击注入后，后端 `demo_scenario_service` 把 fixture 里的感知读数写到 `sensor_readings` 表，同时创建或更新 `crop_seasons` 茬次记录。这是幂等操作——重复注入不会产生重复数据。无硬件也能演示真实的数据流。"

---

### 步骤 6 — 启动 AI 综合巡检（2 min）

**操作**：点击"开始 AI 综合巡检"按钮

**预期效果**：
- 中间 Agent 时间线开始流式输出：
  - `start` → `context_loaded` → `skill_selected` → `plan`
  - `step_start` → `tool_call`（调用 farm_inspect）→ `step_complete`
  - `proposal_created` → `report` → `complete`
- 右侧提案列表出现新提案

**讲解要点**：
> "LangGraph 把 Agent 的判断变成可审计的步骤。每条风险都带证据——不是 LLM 拍脑袋，而是基于确定性规则和传感器实测值。SSE 流式输出让评审能看清每一步。"

---

### 步骤 7 — 风险卡片解读（1.5 min）

**操作**：等待巡检完成，左侧风险态势区显示风险卡片

**预期效果**：
- 出现 `weather.rainstorm_drainage` 风险卡片，severity=high
- 证据列表显示：
  - measured：土壤含水量 95%
  - measured：降雨量 158mm
  - rule：触发暴雨内涝排水规则

**讲解要点**：
> "这条 high 风险来自确定性规则——当土壤含水量 ≥ 90% 且日降雨 ≥ 100mm 时触发。证据链完整：实测值 + 规则 + 推断。保证比赛现场可复现，不依赖 LLM 的随机性。"

---

### 步骤 8 — 批准排水清沟提案（1.5 min）

**操作**：
1. 在右侧提案列表点击"批准"
2. 确认决策说明（可填"同意排水"）
3. 提交

**预期效果**：
- Toast 提示"提案已批准，任务已生成"
- 提案状态变为 approved
- 下方 FarmTaskBoard 出现新任务"排水清沟"，状态 pending

**讲解要点**：
> "人工最终拍板。AI 只起草提案，不直接执行。批准后自动生成结构化任务，包含验收标准、优先级、指派人。这是 AI 辅助决策的边界——人机协同。"

---

### 步骤 9 — 任务执行闭环（2 min）

**操作**：
1. 在 FarmTaskBoard 点击任务的"开始"按钮 → 状态变 in_progress
2. 点击"提交" → 填写执行说明 + 可选附件 → 状态变 submitted
3. 等待 AI 复核（自动触发 task_verification run）→ 状态显示 verdict
4. 点击"完成" → 状态变 completed

**预期效果**：
- "近 14 天事件流"时间线出现新事件：来源"任务完成"，类型"排水"，操作人显示当前用户
- 事件详情含投入品摘要、关联任务 ID

**讲解要点**：
> "任务完成时自动写一条 FarmEvent——这是不可变记忆。下次 AI 巡检时，snapshot 会带上这条事件，让 Agent 知道'7 天前刚排过水'，避免重复决策。这就是反馈闭环。"

---

### 步骤 10 — 切到 pest_outbreak 场景，展示 AI 记忆（1.5 min）

**操作**：
1. 在场景选择器切换到"虫害爆发"
2. 点击"注入感知数据"
3. 再次点击"开始 AI 综合巡检"
4. 等待报告生成，查看报告中是否引用历史事件

**预期效果**：
- 感知面板出现 A2 地块的虫情读数：草地贪夜蛾 35 头/灯、被害率 18%、NDVI 0.62
- 巡检报告生成 `pest.outbreak` high 风险 + 喷药提案
- 报告中可能引用"7 月 18 日刚执行过排水作业"等历史上下文

**讲解要点**：
> "事件流让 AI 有记忆。同一个农场、不同时间点的场景切换，Agent 能看到 25 天前的排水作业，在报告中给出'本轮转旱需注意水分管理切换'之类的连贯建议。这是单次推理做不到的——需要事件溯源支撑。"

## 四、常见问题应对

### Q1：注入场景时提示"地块与场景不匹配"

**原因**：农场缺少 fixture 要求的地块（如 A1/A2/A3）

**应对**：先到 Farms 页面补建地块，名称必须与 fixture 一致

### Q2：巡检长时间无响应

**原因**：LLM API（DashScope）未配置或额度不足

**应对**：
```bash
# 检查 .env 中 DASHSCOPE_API_KEY
# 或切换到 DeepSeek / 本地 Ollama
```

### Q3：健康分卡在 0 分

**原因**：历史提案未清理，积压了大量 pending 提案

**应对**：在 FarmAgent 页面批量拒绝旧提案，或重建数据库

### Q4：前端页面空白

**原因**：前端构建产物未更新

**应对**：
```bash
cd frontend-react
npm run build  # 重新构建
```

### Q5：SSE 流式中断

**原因**：网络波动或后端重启

**应对**：刷新页面，重新选择农场和场景，再次启动巡检

## 五、演示后答疑要点

1. **数据真实性**：fixture 数据基于真实农事场景设计，阈值参考农业行业标准
2. **可扩展性**：接入真实硬件只需替换 `sensor_readings` 的写入来源，上层逻辑无需改动
3. **多农场支持**：所有查询按 `farm_id` 隔离，支持多租户
4. **审计合规**：每个任务的状态转换都有 `TaskExecutionAuditEntry` 记录，不可篡改
5. **风险规则可配置**：阈值常量集中在 `farm_risk_service.py` 顶部，可按作物/区域调整
