# 独立天气查询模块下线设计

## 目标

天气信息只服务于已定位的农场。用户在“农场管理”中查看当前农场的实时天气和天气风险；不再提供按城市或浏览器定位的独立天气查询模块。

## 保留范围

- 农场管理页的天气面板和风险提示。
- `GET /api/v1/farms/{farm_id}/weather`，作为农场页面唯一的 Web 天气接口。
- `weather_service` 及 AI/工具侧天气能力；它们仍是农场天气聚合和对话能力的基础依赖。

## 删除范围

- 前端 `Weather` 页面、`/workspace/weather` 路由和工作台天气入口。
- 顶部导航中的城市天气徽标及其跳转。
- 仪表盘的独立天气查询卡片、天气摘要和其城市天气请求。
- 仅供以上独立页面使用的前端天气 API、通用天气类型。
- 独立 Web 路由 `app/api/v1/weather.py` 及其在应用中的注册。

## 不在范围内

- 不删除天气服务配置、天气数据提供方或 AI Skill/MCP 工具。
- 不更改农场天气的响应契约、缓存策略或天气风险展示。
- 不迁移、不删除历史记录中的既有 `weather` 类型数据。

## 行为与容错

用户从农场管理页查看天气；农场没有坐标或天气服务不可用时，继续显示现有的不可用状态。旧的 `/workspace/weather` 不再由前端注册，因此会落入现有未匹配路由处理；后端独立 `/api/v1/weather*` 端点不再暴露。

## 验收

1. 页面和顶部导航不再出现“天气查询”入口或城市天气徽标。
2. 仪表盘不再请求或展示独立城市天气。
3. 农场管理页仍可请求并展示 `farm-weather`。
4. 前端构建、后端相关测试通过；仓库中无前端对独立 `/weather` API 的引用。
